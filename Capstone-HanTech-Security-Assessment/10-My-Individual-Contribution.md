# 10 – My Individual Contribution

## Role: Group Leader and Vulnerability Assessment Team Member

As the group leader for the HanTech cybersecurity capstone project, I helped coordinate the team's activities and contributed directly to the practical vulnerability assessment and documentation of the project.

My responsibilities covered both team coordination and hands-on technical work.

## 1. Leadership and Team Coordination

- Coordinated the group's activities and helped organise the work required to complete the capstone.
- Communicated project tasks and encouraged members to participate in their assigned responsibilities.
- Supported collaboration and information sharing among team members.
- Helped monitor progress and maintain focus on the project objectives and deliverables.
- Contributed to bringing the team's technical findings and GRC recommendations together into a structured project.

## 2. Hands-on OpenVAS Vulnerability Assessment

I personally carried out the OpenVAS vulnerability assessment against the Metasploitable 2 training machine (`10.0.2.5`) in a controlled lab environment.

My technical contributions included:

- Setting up and running the vulnerability scan using OpenVAS.
- Reviewing the scan report and examining the identified security findings.
- Applying the report's Quality of Detection (QoD) filtering to focus on findings with stronger detection confidence.
- Selecting five significant vulnerabilities for further analysis.
- Reviewing the affected services, port numbers, CVSS scores, QoD values, and available vulnerability references.
- Examining the potential security implications of each finding.
- Documenting the assessment results and retaining screenshots as supporting evidence.

## 3. Vulnerability Analysis and Risk Assessment

I contributed to interpreting the selected findings and explaining how they could affect an organisation.

The five vulnerabilities examined were:

1. MySQL root account with an empty password.
2. Potentially compromised vsftpd 2.3.4 software package.
3. Passwordless root access through rlogin.
4. DistCC remote code execution vulnerability.
5. Default credentials on the Apache Tomcat Manager interface.

I helped connect the technical findings to potential business consequences, including unauthorised access, data exposure, system compromise, and service disruption.

I also contributed to the risk assessment and the development of practical security control recommendations.

## 4. Security Governance and Project Documentation

As part of the wider team effort, I contributed to connecting the technical findings with governance and compliance considerations. This included work on security controls, policy recommendations, cloud security considerations, and the executive-level presentation of the project's findings.

The project documentation was structured to show how technical vulnerability identification can support risk management and security governance.
