# 09 – Conclusion and Lessons Learned

## Conclusion

The HanTech cybersecurity capstone project provided an opportunity to examine how technical vulnerabilities can create serious security and business risks for an organisation. Through our simulated assessment, we identified five critical vulnerabilities affecting services on the Metasploitable 2 test machine. These included weak database authentication, an insecure FTP service, passwordless remote root access, a vulnerable DistCC service, and default credentials on the Tomcat Manager interface.

The OpenVAS assessment helped us identify and examine these weaknesses, while our risk assessment considered their potential impact on confidentiality, integrity, and availability. We then developed security control recommendations and governance policies aimed at reducing the identified risks. The cloud security section also highlighted the importance of secure identity and access management, data protection, continuous monitoring, and understanding the shared responsibility model.

One important lesson from this project is that identifying a vulnerability is only the beginning of effective security management. Organisations must understand the risk behind each finding, prioritise remediation, implement appropriate controls, and regularly review their security posture. Technical tools are valuable, but they must be supported by effective policies, accountability, and continuous improvement.

As the group leader, I also gained practical experience coordinating team activities, encouraging collaboration, and helping the group maintain progress towards its objectives. Personally carrying out the OpenVAS assessment strengthened my understanding of vulnerability scanning, interpreting technical findings, and translating security weaknesses into potential business impacts and practical recommendations.

Although the technical assessment was conducted in a controlled lab using Metasploitable 2, the findings provided useful lessons that can be applied when assessing real organisational environments. The cloud security review was conceptual and was not based on a live cloud infrastructure scan.

Overall, this project strengthened our understanding of the relationship between vulnerability management, risk assessment, security controls, and governance. It reinforced the importance of taking a proactive, structured, and risk-based approach to cybersecurity.

## Lessons Learned

1. **Vulnerability scanning is a starting point:** Scanner findings must be reviewed and interpreted before decisions are made.
2. **Technical severity and business risk are different:** CVSS scores help communicate technical severity, but business context is also necessary when prioritising remediation.
3. **Access control is essential:** Weak passwords, default credentials, and unnecessary privileged access can expose critical systems.
4. **Security requires more than technology:** Policies, procedures, accountability, and staff awareness support effective technical controls.
5. **Cloud security is a shared responsibility:** Organisations must understand which security responsibilities belong to the cloud provider and which remain theirs.
6. **Teamwork and coordination matter:** Clear communication, task coordination, and shared responsibility help a team deliver a structured project.
7. **Evidence and documentation are important:** Recording scan results, assessment decisions, limitations, and recommendations makes security work easier to review and communicate.

## Final Reflection

This capstone has been an important step in my cybersecurity development. It allowed me to move beyond learning security concepts and apply them through a practical vulnerability assessment and a broader GRC perspective. I have gained more confidence in using OpenVAS, analysing findings, understanding risk, and communicating security recommendations. I intend to build on this experience through further hands-on labs and continuous learning.
